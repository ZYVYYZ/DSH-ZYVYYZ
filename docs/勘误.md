# 勘误

> 有错就说，不必客气。**我们宁愿被指出来，也不愿意错着被人当参考。**

## 怎么报

1. **GitHub Issue**（最稳）：写清「哪一版、哪一页/哪一节、原文一句、你认为错在哪」；
2. **邮箱 / QQ 群**：不公开报也行，我们会替你匿名记进这里。

## 我们怎么处理

- **不改原文，只加注**：书里坚持"只增不改"，错的地方**留原样**，在下面加一条带日期的更正——**你能看见我们错过什么，这比一本干净的书有用**；
- 每一条都会进这里，写清"谁先发现的"（除非你要求匿名）。

## 已知的（点出来就是给自己难堪）

- 早期版本里有两处写"会话跑到 92%"，那是**凭印象写的数**，已删；
- 早期版本里有一处指路写成 `模板/现场.md`，实际文件叫 `模板/现场-片段.md`，已改；
- 书里报的支出（十几天、一万多元）是**作者自己报的数**，**没有对过账单**，大半是盘和 NAS；
- **快照恢复、冷备还原，我们自己一次都没演练过**——写着有，实际不知道。
