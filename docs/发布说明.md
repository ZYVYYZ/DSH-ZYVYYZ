# 发布说明（v0.4.1）

## 这次发什么

- `book/人教版/` —— 书本体，**一章一份 PDF**（`入门/` `进阶/` `速成/` 按文件夹放）；每页都印了一行浅色水印 `ZYVYYZ · github.com/ZYVYYZ/DSH-ZYVYYZ`；
- `book/鱼教版/` —— 给鱼读的那版，同样一章一份；
- `book/丈育版.pdf` —— 两页版，没有术语；
- `kit/` —— 给 AI 吃的包（含模板、脚本、清单）。

## 这次为什么发

**修包，书的内容没改一个字。**

v0.4 的包有个硬伤：解压后 `README.md` / `安装.mjs` / `校验.mjs` 的权限是 **0**，Mac 和 Linux 上打不开——「解压即用」和「自己跑一遍校验」在那两套系统上不成立。打包脚本漏了统一 chmod，这一版补上。

另外，v0.4 发出后做了两轮**黑盒验收**：起两条干净会话，一条只读传火包的 `README.md`，一条只读 `00-给鱼的.md`。**两个都走不完**，而且各自独立地指出同一件事：**从头到尾没有一步说了「做到什么样算成了」。** 这一版把两份说明重写了。
>
> 改完又测了两轮，才发现「怎么算搭好了」那一节站不住：它测的是「AI 这一轮答不答得出」，不是「这张纸接不接得上」——说得出不等于说得对，说得对也可能只是碰上了一个脾气好的模型。**所以那一节砍了**，换成「当场只能查这三件」，并写明：**「接得上」当场验不出来，唯一能证明它的是下次真的关会话。**
>
> 第八轮定点回访还抓到一个：A/B 两路的分法，原来用「它读不读得到文件」判断，但网页版能上传附件，传上去也「读得到」——那是一次性的。改成「**新开一个会话，什么都别传，只让它读路径**」，测的才是持久的权限。

## 校验

| 文件 | SHA256 |
|---|---|
| 文本包 `DSH-ZYVYYZ-kit-v0.4.1.zip` | `33c8e5ed404818ce5a02ebadd06ac31dfb3ececf57e651e393b63ccfe514d94e` |
| 传火包 `DSH-ZYVYYZ-chuanhuo-v0.4.1.zip` | `dda90e58ac8c68d202930b999984c14342a448837b82ce5da07c2e4da53f0e22` |

**捆绑包 `DSH-ZYVYYZ-v0.4.1.zip` 的哈希不写在这份文件里**——它在捆绑包内部，写进去就变成自己算自己。以 GitHub Release 页面上那个为准（GitHub 自己算的，我们改不了）。

**每份 PDF 的末页印的是"文本包"的完整 SHA256**，因为 PDF 不能印包含它自己的那个包的哈希。文本包（文件名用 ASCII：GitHub 附件名对中文不友好，中文名会丢字）就是给人下载的那份 `DSH-ZYVYYZ-kit-v0.4.1.zip`（kit + 安装脚本）——和 PDF 里印的那个值对上，说明两样东西出自同一次打包。

三个包都是**可复现**的：连跑两次打包，哈希一样（打包时钉死了文件时间与权限）。

## 三种验法

1. **对哈希**：跟上面这张表、或 GitHub Release 页面上的资产摘要比；
2. **对 PDF**：随便翻开一本书的最后一页，印着一串 SHA256，那是文本包的；
3. **跑校验**：解压后在包根跑 `node 校验.mjs`（要 Node 18+），它按 `清单.sha256` 重算每个文件。

⚠️ 第三种只能证明**文件没坏**。清单和被校验的文件在同一个包里，一起被换掉就查不出来。要证明**来源**，只能对 Release 页面上的哈希——那是 GitHub 自己算的。

## 锚点

- 以 **Release 发布时间 + 资产 SHA256** 为准；
- **不写"最早"**——我们无法证明谁先谁后。
