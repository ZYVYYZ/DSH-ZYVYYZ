# 发布说明（v0.4.1）

> **急修版。如果你已经下过 v0.4，请换这一个。**

## 这次发什么

- `book/人教版/` —— 书本体，**一章一份 PDF**（`入门/` `进阶/` `速成/` 按文件夹放）；每页都印了一行浅色水印 `ZYVYYZ · github.com/ZYVYYZ/DSH-ZYVYYZ`；
- `book/鱼教版/` —— 给鱼读的那版，同样一章一份；
- `book/丈育版.pdf` —— 两页版，没有术语；
- `kit/` —— 给 AI 吃的包（含模板、脚本、清单）。

## 这次为什么发

**v0.4 的包在 Mac 和 Linux 上打不开。**

解压后 `README.md` / `安装.mjs` / `校验.mjs` 的权限是 **0**——「解压即用」和「自己跑一遍校验」在那两套系统上都不成立。原因是我们打包脚本漏了统一 `chmod`。Windows 上感觉不到，所以一直没发现。

同一天还修了四处，都是我们自己的错：

- **传火包的两份说明重写了。** 起因是两轮黑盒验收：起两条干净会话，一条只读 `README.md`、一条只读 `00-给鱼的.md`，**两个都走不完**，而且各自独立地指出同一件事——从头到尾没有一步说了「做到什么样算成了」。改完又测了三轮，发现「怎么算搭好了」那一节根本站不住（它测的是 AI 这一轮答不答得出，不是这张纸接不接得上），于是把那一节砍了，换成「当场只能查这三件」，并写明：**「接得上」当场验不出来，只能等下次真的关会话**。
- **`安装.mjs` 装完还打印「懒人包 v0.4」**，已改成 v0.4.1。
- **仓库根校验器不跳过 `.git/`**：在 git clone 里跑，会把 git 自己那几百个文件算进来，写出的清单是错的，最后判「这不是原件」。PC 上实测 296 个文件、162 处多出。现在跳过 `.git` / `.github` / `node_modules` / `.cache`。
- **删掉 v0.3 遗留的 `kit/先读这个.txt`**：v0.4 已改名成 `README.md`，但同步脚本只加不删，这个文件在仓库里留到了现在。

**书的正文一个字没改。** PDF 因末页哈希变化而重印。

## 校验

| 文件 | SHA256 |
|---|---|
| 文本包 `DSH-ZYVYYZ-kit-v0.4.1.zip` | `304ae168944f2a70ee4daba3aabb3065d8afb5a4e9ee4c9a4d983ca7b7cb2384` |
| 传火包 `DSH-ZYVYYZ-chuanhuo-v0.4.1.zip` | `6d0d4dbcffb59807874cb3aa90a03e1f0dc1ad23db2956c7e8511f4f3c745862` |

**捆绑包 `DSH-ZYVYYZ-v0.4.1.zip` 的哈希不写在这份文件里**——它在捆绑包内部，写进去就变成自己算自己。以 GitHub Release 页面上那个为准（GitHub 自己算的，我们改不了）。

**每份 PDF 的末页印的是"文本包"的完整 SHA256**，因为 PDF 不能印包含它自己的那个包的哈希。文本包（文件名用 ASCII：GitHub 附件名对中文不友好，中文名会丢字）就是给人下载的那份 `DSH-ZYVYYZ-kit-v0.4.1.zip`（kit + 安装脚本）——和 PDF 里印的那个值对上，说明两样东西出自同一次打包。

三个 zip 都是**可复现**的：连跑两次打包，哈希一样（打包时钉死了文件时间与权限）。

⚠️ 但 **PDF 不是逐字节可复现的**：同一批 md 渲染两次，文件会差十几字节（PDF 内部带时间戳）。所以 `清单.sha256` 只对**同一次构建**有效——包里的清单和包里的文件对得上；拿另一次构建的清单来比，会差几处，那不是篡改。

## 三种验法

1. **对哈希**：跟上面那张表、或 GitHub Release 页面上的资产摘要比；
2. **对 PDF**：随便翻开一本书的最后一页，印着一串 SHA256，那是文本包的；
3. **跑校验**：解压后在包根跑 `node 校验.mjs`（要 Node 18+），它按 `清单.sha256` 重算每个文件。

⚠️ 第三种只能证明**文件没坏**。清单和被校验的文件在同一个包里，一起被换掉就查不出来。要证明**来源**，只能对 Release 页面上的哈希——那是 GitHub 自己算的。

## 锚点

- 以 **Release 发布时间 + 资产 SHA256** 为准；
- **不写"最早"**——我们无法证明谁先谁后。
